# Full multi-layer decoder loop C++ port — status & integration note

## What was ported

A **generic one-token decoder forward loop** (`DecoderModel` / `run_decoder_step`)
that assembles the already-verified bit-exact primitives into the complete
`Qwen4ExpModel.__call__` compute path for batch=1, seq=1:

```
embed_tokens -> tile(1,1,hc_count) -> [ per-layer:
    attn hyper-connection -> GDN linear attention -> inject
    mlp  hyper-connection -> EXACT-router MoE      -> inject ]
 -> final hyper-connection mixer -> lm_head -> logits
```

No existing file was modified and no primitive was reimplemented. Four new
files were added (see "Files" below).

## Composition — every call is a verified primitive

`decoder.cpp::run_decoder_step` maps one Python layer one-for-one:

| Python op | C++ primitive (header) |
|---|---|
| `attn_hyper_connection(hidden)` | `gated_residual()` (`engine.hpp`) |
| `self.linear_attn(mixed, cache)` | `gdn_layer_forward()` (`gdn_layer.hpp`) |
| `hyper_input + (branch[...,None,:] * inj[...,None])` | `inject_branch()` (reshape/expand_dims, `decoder.cpp`) |
| `mlp_hyper_connection(hidden)` | `gated_residual()` |
| `gate(x) -> softmax(precise) -> argpartition -> renorm` | `router()` (`engine.hpp`, `renorm_blend=0`) |
| `switch_mlp(x, inds) -> score combine` | `moe_block()` (`engine.hpp`) |
| `hyper_connection_mixer(hidden) -> lm_head` | `final_head()` (`engine.hpp`) |

Per-layer caches are `DecoderLayerCache { GDNCacheState gdn; QSACache qsa; }`;
the GDN half is threaded through `gdn_layer_forward` and updated in place for
the next token. The QSA half is carried for future full-attention layers.

## The silu caveat — and how bit-exactness is guaranteed

The verified C++ primitives implement `silu(x) = x * sigmoid(x)` with explicit
MLX ops, while the real `mlx_vlm` modules call the fused `nn.silu`, which
differs by ~1 ULP for `|x| >= 0.5`. The generator therefore:

1. keeps all silu inputs (hc `low`, MoE gate activations, GDN conv output)
   small by seeding weights with a small scale, and
2. **computes the whole step twice** — once through the real modules
   (`expected_logits`) and once through a primitive-formula reference that
   uses explicit sigmoid and the same one-centered norms / `gather_qmm` /
   fused gated-delta kernel (`expected_logits_primitive`) — then **asserts the
   two are byte-identical**. Generation aborts if the assertion fails.

This makes the "real model" reference and the C++ primitive path provably the
same computation, not merely close. The chosen scales satisfy it for seeds
`20261117`, `1`, `12345`, `999` (all verified). If you change scales/seed, keep
that self-check green.

## Integration instructions

1. **Build**: add `src/decoder.cpp` to `CMakeLists.txt` (no changes were made to
   it here — the owner must do that) and link the same MLX target as the other
   engine sources.
2. **Load weights**: populate `DecoderLayerWeights` / `DecoderHeadWeights` from
   `ExpertStore` (or `mx::load` during bring-up). `Q4Projection` / `GDNWeights`
   need their constructor args; the field layout matches `nn.Linear` `[out,in]`.
3. **Config from `ModelSpec`**: `model_adapter.hpp` defines a *second*
   `GDNConfig` in `veystrix::engine`, which collides with `gdn_layer.hpp`'s
   `GDNConfig`. Therefore `decoder.hpp` deliberately does not include
   `model_adapter.hpp`. Map the scalars explicitly, e.g.:
   ```cpp
   DecoderConfig cfg;
   cfg.hidden_size = spec.hidden_size;
   cfg.n_layers    = spec.n_layers;
   cfg.hc_count    = spec.hc.hc_count;
   cfg.hc_lowrank  = spec.hc.hc_lowrank;
   cfg.eps         = spec.norm_eps;
   cfg.gdn = GDNConfig{spec.hidden_size, /*key_dim*/Hk*Dk, /*value_dim*/Hv*Dv,
                       Hk, Hv, Dk, Dv, K, spec.norm_eps,
                       GDNActivation::Sigmoid};  // from from_qwen_config scalars
   ```
   (A future cleanup should rename one of the two `GDNConfig` structs so both
   headers can coexist.)
4. **Caches**: initialize one `DecoderLayerCache` per layer with zeroed
   `conv_state [1,K-1,conv_dim]` and `recurrent_state [1,Hv,Dv,Dk]` (f32), then
   pass the same vector to each successive `run_decoder_step` call — the
   function updates the GDN state in place.
5. **MoE routing**: `renorm_blend` must be `0.0f` to match the production MoE
   gate (softmax/argpartition/renorm-by-sum), which is what the generator uses.

## What remains (honest scope)

- **Full-attention (QSA) branch is NOT composed.** `qsa_full.hpp`'s indexer
  produces a sparse KV mask, but the downstream sparse-attention kernel and its
  integration into the layer's attention branch are not wired into
  `run_decoder_step`. The validated config is all-linear, so this does not
  affect the proven result. For a mixed stack, a full-attention layer would
  need a `branch = full_attention(mixed, qsa_mask, kv_cache)` path plus its
  weights; this is the largest remaining piece.
- **Prefill (S > 1)** is not bit-exact: the Python prefill uses a different
  full-conv + chunked-scan path. `gdn_layer_forward` iterates the decode path
  token-by-token for S > 1, which is not the same computation.
- **Shared expert** in the real MoE is not implemented as a primitive; the
  test config zeroes it. For a production checkpoint with a non-trivial shared
  expert, add a `shared_expert` primitive (dense MLP + sigmoid gate) and its
  contribution to the MoE branch.
- **Sampling / I/O / server bridge** are unchanged and out of scope here.

Concrete next step: wire the full-attention branch (QSA indexer mask + sparse
attention) and a non-zero shared expert, then re-run this generator with a
mixed `layer_types` config to extend bit-exactness beyond all-linear layers.
